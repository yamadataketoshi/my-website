ドメイン駆動開発（DDD）とは

今回はドメイン駆動開発（Domain-Driven Design, DDD）について勉強してきたことを共有していきたいと思います。

ドメインとは​

そもそもドメインとは一体どういったものなのか？

ドメインとは「領域」という意味の単語であり、その名の通りビジネスの特定の領域を指します。ドメイン駆動開発では、このビジネス領域に焦点を置いて開発を行う手法です。

ドメインの具体例​

ビジネス領域に焦点を置いて開発を行う...と言われても分かりにくいと思うので、具体例を出したいと思います。

YouTubeを例に考えていこうと思います：

ユーザードメイン​

  • 氏名
  • 表示名
  • 年齢
  • メールアドレス
  • 電話番号
  • ID
  • パスワード
  • 登録日時
  • アカウント状態（有効/無効）

動画ドメイン​

  • タイトル
  • 説明文
  • 投稿日時
  • 視聴回数
  • タグ
  • 動画ファイル
  • サムネイル
  • 公開設定（公開/非公開/限定公開）

コメントドメイン​

  • コメント内容
  • 投稿者（ユーザー）
  • 投稿日時
  • いいね数
  • 返信先コメント（返信の場合）
  • コメント状態（表示/非表示）

ドメインの重要性​

ドメインとは、このようなビジネス上の概念やデータの集合体だと思ってもらえたらいいと思います。

重要なのは、これらのドメインが単なるデータの分類ではなく、ビジネスの現実世界を反映した概念的な境界であることです。例えば、ユーザードメインは「YouTubeを利用する人」という現実の概念を表現しており、単にユーザー情報を格納するデータベースのテーブルとは異なる意味を持っています。

ドメイン設計の考慮点​

もちろん、データの切り分け方は実務上でどういった集合体を作った方が扱いが分かりやすいのかや保守しやすいのかなどを考えながら設計されます。

設計時の重要なポイント：​

1. ビジネスルールの反映 各ドメインには、その領域に固有のビジネスルールが存在します。例えば、動画ドメインでは公開設定や著作権に関するルールなどが考えられます。これらのルールを適切にドメイン内に表現することが重要です。

2. 責任の明確化 どのドメインがどの責任を持つかを明確にすることが必要です。動画ドメインは動画の公開・非公開の制御などを担当します。責任が曖昧だと、どこで何を変更すればよいかが分からなくなってしまいます。

先ほどのドメインの例だと動画ドメインの中にコメントがあったとお思いますが、このコメントの編集機能をコメントドメインではなく動画ドメインで行ってしまうとコメントに対する責任の所在が不明確になってしまいます。

3. 変更の影響範囲 ドメイン間の依存関係を最小限に抑えることが重要です。一つのドメインの変更が他のドメインに大きな影響を与えると、システム全体の保守が困難になってしまいます。例えば、ユーザードメインの変更が動画ドメインやコメントドメインに大きな影響を与えないよう、適切な境界を設ける必要があります。

4. 拡張性 将来的な機能追加を考慮した設計が求められます。例えば、現在の動画ドメインにライブ配信機能を追加する場合、既存の設計を大きく変更することなく拡張できるよう、事前に考慮しておくことが重要です。

ドメイン駆動開発の利点​

このようにドメインを明確に分離することで、多くの利点が得られます。

次に、保守性の向上が期待できます。変更の影響範囲が明確になるため、修正が必要な箇所を特定しやすくなります。また、各ドメインが独立しているため、一つのドメインの変更が他の部分に波及するリスクを最小限に抑えられます。

さらに、テスタビリティの向上も大きな利点です。各ドメインを独立してテストできるため、テストの作成や実行が容易になり、品質の向上につながります。

最後に、チーム開発の効率化が実現できます。責任の分離により、複数の開発者が異なるドメインを並行して開発できるようになり、開発スピードの向上が期待できます。
